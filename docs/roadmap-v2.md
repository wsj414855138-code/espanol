## 1. 最大短板：学习数据是"孤岛"（对标 AnkiWeb/Duolingo 云同步）

现状：SRS 进度、统计存在**手机浏览器 localStorage**。问题：

1. **会丢**：清缓存/换浏览器/换手机 → 全部清零
2. **不可分析**：无法回答"这周练了几次？哪个音素总错？复习曲线什么样？"
3. **喂料者盲区**：你（内容投喂者）看不到她练得怎么样 → 无法调整内容
4. **换设备断档**：手机学完电脑看不了

对标结论：Duolingo/AnkiWeb 的留存都建立在"进度在云端"之上。**数据上云是 v0.5 的第一优先级。**

## 2. 数据架构方案（决策点 A）

数据量极小（SRS 状态 + 每日活动日志 + 评分记录 ≈ 每天几 KB JSON），单学习者，无需复杂账号体系。

| 方案 | 成本 | 国内访问 | 鉴权 | 适配度 |
|---|---|---|---|---|
| **Supabase**（✅ 已决策 2026-08-15） | 免费 500MB PG + 认证 | ⚠️ 需梯子（她本就挂梯子用 GitHub Pages） | 内置 Auth + RLS | 高；免费额度大、生态好 |
| 腾讯云 CloudBase | 免费额度 | ✅ 快 | 匿名登录/自定义密钥 | 中（备选） |
| COS 存 JSON | 几毛/月 | ✅ 快 | 签名 URL 写、公开读 | 中；需云函数配合 |
| 导出/导入 + iCloud | 免费 | ✅ | 无 | 低；体验差，放弃 |

**决策（2026-08-15）：Supabase**。单用户免账号密码：首次打开匿名身份 + RLS 限定；**断网时本地缓存兜底，联网自动合并**（梯子断连不丢数据）。

> 原则：**单学习者不做账号密码**（Duolingo 式账号体系是给多用户的；我们要的是"免打扰"）。

## 3. 分阶段迭代计划

### v0.5 · 数据上云 + 离线兜底（先做，1-2 周）

- 首次进入自动注册匿名身份（无需她做任何操作）
- **验收**：清缓存/换设备 → 进度还在；电脑端能查到手机端的数据
- ✅ **已完成（2026-08-16）**：cloud.js 匿名身份+SRS/统计同步+离线兜底；冒烟测试+回归全绿
- SpeechSuper 评分代理：Supabase Edge Function 持 key（不暴露给网页），与 v0.8 同实现

### v0.6 · 学习报告（喂料者 + 学习者双视角）
- 学习者页签"📊 报告"：连续打卡日历（streak 热力图，对标 Duolingo）、今日/本周练习量、正确率趋势、SRS 到期卡片数（对标 Anki 统计页）
- 你的视角（电脑端独立页或会话内工具）：每周自动总结（练了几分钟/薄弱音素/到期量）→ 喂料决策
- **验收**：她能看懂自己的热力图；你每周收到一次自动周报
- ✅ **学习者报告页已完成（2026-08-16）**：📊 页签（连续打卡/今日统计/到期卡/热力图）；喂料者周报待 service_role key

### v0.7 · 动机机制（对标 Duolingo 留存三件套）
- **连续打卡 streak**：数据已在云端，天然支持
- **iOS 提醒**：iPhone 16.4+ 支持"添加到主屏幕"的 PWA 接收 Web Push → 每日固定时间提醒（学习习惯锚点）
- 轻量成就（首次全对/连续 7 天/100 次跟读）——克制，不做 Duolingo 式花哨
- **验收**：她连续 7 天被提醒并打卡

### v0.8 · 手机端音素级发音评分（SpeechSuper，决策点 B）
- 现状痛点：Web Speech 在 iPhone Safari 不可用 → **她手机上学不到评分**（跟读模块缺闭环）
- 路径：申请 SpeechSuper（驰声，唯一支持西语音素级诊断的厂商，调研结论见 speech-eval-research.md）→ 云函数代理调用 → 音素级错误诊断
- **差异化亮点**：评分结果对齐我们的 7 类中文母语难点音素（b/v、p/b、t/d、l/r、r/rr、元音、重音）→ 生成"薄弱音素档案"（ELSA 式），自动把薄弱音素对应听辨题排进复习
- **验收**：跟读后看到"你发成了 X，正确的 b/v 区别是…"

### v0.9 · 对话陪练（决策点 C，延迟启动）

- **验收**：她能完成 5 轮"点餐/问路"场景对话
